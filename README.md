# ЛОВИ ✦

Telegram-бот: отправляешь ссылку → выбираешь формат → получаешь файл в чат.
Русский интерфейс, аккуратные HTML-карточки, inline-кнопки и понятные статусы.

Поддерживаются публичные **YouTube / Shorts, TikTok и Instagram Reels** через yt-dlp:

- 🎬 Видео: доступные ступени от 240p до 2160p, с учётом вертикальных роликов.
- 🎧 Только звук: MP3, 192 кбит/с.
- 🖼 Только обложка: JPG документом, без дополнительного сжатия Telegram.
- ⚡ Повторная отправка через Telegram `file_id`, без повторного скачивания.
- Очередь Redis + arq, независимые workers, лимиты нагрузки и прокси.

Видео скачивается в MP4. При наличии предпочитается H.264; другие кодеки отправляются
файлом без обещания встроенного воспроизведения. Повышать разрешение или перекодировать
видео на сервере не требуется: это бережёт время и CPU.

## Быстрый запуск

Нужны Docker Engine и Compose v2. Токен получите у **@BotFather** через `/newbot`.

```bash
cp .env.example .env
# Откройте .env и заполните BOT_TOKEN.
docker compose up -d --build
docker compose logs -f bot worker
```

Откройте созданного бота в Telegram, нажмите **Start** и отправьте ссылку.
Токен, пароли прокси и cookies храните только в `.env` / хранилище секретов.
`.env` и `secrets/` исключены из Git и Docker build context.

В `.env.example` указан `REDIS_URL=redis://redis:6379/0` для Compose.
В обычном Telegram Bot API отправляем файлы до **49 MB**, с запасом к лимиту 50 MB.
Если файл больше — бот предлагает выбрать меньшее качество. Автоматического
ухудшения выбранного качества и тяжёлого перекодирования видео нет.

## Как выглядит чат

Приветствие `/start` отправляет включённый в проект пользовательский GIF
`assets/welcome.gif` в том же сообщении, что и текст с кнопками.
Для замены положите другой GIF в `assets/welcome.gif` перед сборкой Docker-образа.
Для другого пути задайте `WELCOME_ANIMATION_PATH`; также поддерживается MP4
без звука. После замены файла выполните `docker compose build bot`, затем
`docker compose up -d --no-build --force-recreate bot`.
Повторные отправки используют Telegram `file_id`, сохранённый в Redis отдельно
для каждого бота и содержимого файла. При отсутствии или отклонении анимации
бот отправит обычное текстовое приветствие. См. [assets/README.md](assets/README.md).

```text
ЛОВИ / медиа по ссылке

Тот самый ролик — теперь у тебя.
🎬 Видео · 🎧 Аудио · 🖼 Обложка

YouTube · Shorts · TikTok · Reels
─────────────────────────────────
Нашёл ✦
Название ролика
YouTube · 2:34 · Автор

[🎬 360p]  [🎬 480p]  [⚡ 720p]
[🎬 1080p]
[🎧 Только MP3] [🖼 Обложка]
─────────────────────────────────
◌ В очереди → ⚡ Готовлю → 📤 Отправляю → Готово, лови ✦
```

Кнопки формируются по данным конкретного ролика; несуществующие форматы не обещаются.
Качество обозначает верхнюю границу разрешения, исходное видео не увеличивается.
Команды `/start`, `/help`. Использование — в личном чате с ботом.
Название и описание Telegram-профиля устанавливаются при старте; username и аватар
настраиваются в @BotFather. Бот не может менять чужие настройки Telegram-клиента.

## РФ, прокси и доступ к платформам

Для стабильной работы разумно разместить сервер там, где доступны Telegram и нужные
площадки. Прокси настраиваются независимо:

```dotenv
TELEGRAM_PROXY=socks5://login:password@proxy.example:1080
MEDIA_PROXY=http://login:password@proxy.example:3128
```

Это примеры адресов: рабочий прокси нужно предоставить самостоятельно.
Спецсимволы в логине/пароле кодируйте для URL. Поддерживаются HTTP и SOCKS5.
Не отключайте TLS-проверку. Пустой `MEDIA_PROXY` оставляет штатные системные proxy
настройки yt-dlp; `TELEGRAM_PROXY` задаёт прокси aiohttp явно.

Доступ к сайтам и CDN зависит от региона, IP и антибот-проверок. YouTube может
требовать cookies / PO Token, Instagram — вход, TikTok — доступный регион.
Прокси не гарантирует обход этих ограничений. Приватные ролики, DRM, прямые эфиры,
плейлисты и фотоальбомы не поддерживаются.

### Cookies (необязательно)

При необходимости экспортируйте **свои** cookies в Netscape-формате. Это секрет
сессии: используйте отдельный аккаунт и не публикуйте файл. В `compose.yaml`
уже есть read-only mount `./secrets:/run/lovi-secrets:ro`:

```bash
mkdir -p secrets
# Сохраните cookies.txt в secrets/, обеспечьте чтение UID 10001 внутри контейнера.
```

```dotenv
COOKIES_FILE=/run/lovi-secrets/cookies.txt
```

Worker копирует cookies в приватный каталог задачи и удаляет его после завершения.
Для YouTube в образ включены Node.js и `yt-dlp-ejs`. Удалённые challenge-скрипты
не скачиваются автоматически. Если площадка изменила API, обновите yt-dlp с
сохранением lockfile, пересоберите образ и проверьте реальную ссылку:

```bash
uv lock --upgrade-package yt-dlp --upgrade-package yt-dlp-ejs
uv sync --locked
docker compose up -d --build
```

## Большие файлы: собственный Telegram Bot API

Обычный облачный Bot API имеет лимит отправки 50 MB. Для файлов больше нужен
отдельно развёрнутый официальный **telegram-bot-api** в `--local` режиме
(https://github.com/tdlib/telegram-bot-api), с вашими `api_id` / `api_hash`.
В этом режиме поддерживаются загрузки до 2000 MB; в проекте ограничение 1900 MB.

После запуска сервера и перехода бота по официальной инструкции (`logOut` на старом
Bot API перед переключением) укажите:

```dotenv
TELEGRAM_API_BASE=http://your-private-bot-api:8081
MAX_UPLOAD_MB=1900
JOB_TIMEOUT_SECONDS=1800
```

Закройте сервер Bot API от публичного доступа. Worker передаёт файл multipart-загрузкой;
общий файловый путь с сервером Bot API не требуется. Сам сервер Bot API, его
credentials и процедура миграции не создаются автоматически.

## Нагрузка и масштабирование

```text
Telegram → gateway (aiogram) → Redis / arq → workers → yt-dlp + FFmpeg → Telegram
                                   ↕
                   карточки / лимиты / file_id / блокировки
```

- Gateway не скачивает медиа. Метаданные и файлы обрабатывают workers.
- `WORKER_CONCURRENCY=2`, `DOWNLOAD_FRAGMENTS=4`: до двух задач на worker,
  до четырёх параллельных фрагментов на задачу; цель — скорость без перегрузки IP.
- Один активный запрос на пользователя. По умолчанию до 20 задач/час
  (анализ ссылки и скачивание считаются отдельными задачами), пауза 4 секунды.
- До 100 задач в общей очереди/обработке, атомарный admission через Redis Lua.
- Распределённая блокировка не позволяет параллельно скачивать один формат одной ссылки.
- Общий лимитер Telegram: до 22 запросов/сек, пауза между сообщениями в один чат,
  обработка `RetryAfter`. Повторная отправка при сетевой ошибке не выполняется вслепую.
- `file_id` хранится 7 дней, метаданные — 15 минут, карточки — 30 минут.
  Повторные ссылки YouTube / Shorts нормализуются к одному URL.
- Время, размер и место на диске ограничены. По таймауту уничтожается группа
  процессов yt-dlp/FFmpeg. Временные файлы удаляются и при ошибках.

```bash
docker compose up -d --scale worker=3
docker compose exec worker python -m lovi health
```

В polling должен работать **один** `bot`; Redis lease защищает от второго poller.
Для обычного трафика масштабируйте workers. Начните с 2–4 vCPU, 4 GB RAM,
диска 20+ GB и измерьте реальные ролики / сетевой канал. Для больших файлов
планируйте до `4 × MAX_UPLOAD_MB × число одновременно работающих задач` на диске
плюс запас. Скорость зависит от площадок, IP, Telegram и сети; гарантии конкретной
пропускной способности без нагрузочного замера нет.

Для более высокого входящего трафика есть webhook-режим:

```dotenv
BOT_MODE=webhook
WEBHOOK_BASE_URL=https://bot.example.com
WEBHOOK_SECRET=replace-with-at-least-32-random-url-safe-characters
```

Завершайте HTTPS на reverse proxy и направляйте `/telegram` на `bot:8080`.
По умолчанию порт опубликован только на `127.0.0.1:8080`; при необходимости
подключите reverse proxy к сети Compose. Заголовок Telegram secret проверяется;
не раскрывайте его. `/health` проверяет Redis и наличие worker heartbeat.
Не публикуйте Redis или worker в Интернет.

Текущая схема — один gateway и несколько workers с одним Redis. Она не обещает
exactly-once: при падении между отправкой файла и сохранением `file_id` результат
может остаться неизвестным. Автоповтор задач отключён, чтобы не присылать дубликаты;
пользователь может повторить запрос. Задачи, не начавшиеся за `JOB_TIMEOUT_SECONDS`,
истекают; lease пользователя освобождается с запасом по TTL. После отказа очереди
может понадобиться повторная ссылка. Для полноценной высокой доступности нужны
отдельные Redis HA, мониторинг, стратегия webhook dedup и нагрузочные испытания.

## Локальная разработка и проверки

Python 3.12+, uv, Redis 7+, FFmpeg/ffprobe и Node.js 22+.

```bash
uv sync --locked
cp .env.example .env
# BOT_TOKEN — ваш токен; REDIS_URL=redis://localhost:6379/0; DATA_DIR=./data.
docker compose up -d redis
```

Redis в Compose не публикует порт. Для локальных Python-процессов запустите отдельный
Redis на localhost или используйте `compose.dev.yaml`:

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d redis
uv run python -m lovi worker
# В другом терминале:
uv run python -m lovi bot
```

```bash
uv run ruff check .
uv run pytest -q
```

Тесты используют fake Telegram / yt-dlp и изолированный Redis-совместимый backend.
Проверяют нормализацию ссылок, защиту чужих карточек, лимиты, форматы, кэш,
обработку ошибок и удаление временных файлов. Живой тест требует BOT_TOKEN,
доступных IP/прокси и реальных ссылок: `/start` → YouTube → 720p, MP3, обложка →
тот же файл повторно → TikTok → Reels → Shorts. Сравните повторную отправку в логах:
`outcome=cache`. Нельзя считать эти живые проверки пройденными только по unit-тестам.

## Диагностика ошибки загрузки

Сборка включает официальный extra `yt-dlp[curl-cffi]`: Instagram использует этот
backend для части запросов с имитацией браузера. Его наличие не гарантирует доступ
с любого IP и не отменяет ограничения аккаунта, региона или частоты запросов.

Для проверки одной ссылки с настройками worker, без Telegram и очереди:

```text
docker compose run --rm --no-deps worker python -m lovi diagnose "https://www.instagram.com/reel/DctUTDnNSWx/"
```

Команда возвращает JSON с версией yt-dlp, наличием curl-cffi, признаками настройки
прокси/cookies, `code` и `reason`. Значения секретов, ссылки CDN и cookies не печатаются.
Логи обычных задач теперь также содержат фиксированный `reason`.
`login_required` означает явное требование входа, `empty_media_response` — пустой
ответ Instagram (он сам по себе не доказывает необходимость cookies),
`rate_limit_or_login` — неоднозначный ответ о лимите или входе,
`proxy_407` — отказ авторизации прокси, `network_timeout` — сетевой таймаут.
Исходные ответы сайтов в логи не выводятся.

Если карточка открывается, но скачивание зависает, проверьте именно медиасервер:

```text
docker compose run --rm --no-deps worker python -m lovi diagnose "https://www.instagram.com/reel/DctUTDnNSWx/" --cdn --height 720
```

Режим `--cdn` извлекает форматы один раз и через тот же прокси читает не более
1024 байт каждого выбранного потока. Он передаёт заголовки исходного потока,
закрывает соединение после пробы и не сохраняет видео. Это проверка доступности,
а не подтверждение полной загрузки. JSON содержит `cdn_checks`, только имя хоста
CDN (без подписанной ссылки), HTTP-статус и число прочитанных байт. При отказе
возвращаются `stage=metadata/media/postprocess`, причина и `cdn_host`, если он известен.
Ответ HTML вместо медиа обозначается `media_not_video`.

Для проверки полной загрузки и ffprobe без отправки в Telegram есть отдельный режим:

```text
docker compose run --rm --no-deps worker python -m lovi diagnose "https://www.instagram.com/reel/DctUTDnNSWx/" --download --height 720
```

Он использует тот же Downloader, ограничения размера/времени/длительности, что и
обычная задача, и удаляет файл после проверки. Успех содержит `check=full_download`,
измеренную длительность, размеры кадра и `download_bytes`. Полный путь и секреты
не печатаются. `--cdn` и `--download` нельзя включать одновременно.

Для Instagram браузерный профиль curl-cffi теперь применяется и при получении
метаданных, и при загрузке файлов. При одинаковом разрешении и кодеке выбирается
готовый MP4 со звуком, если он есть, чтобы не открывать лишние потоки через прокси.
`MEDIA_SOCKET_TIMEOUT_SECONDS` (по умолчанию 20, диапазон 5–120) управляет таймаутом
отдельного соединения; увеличение не отменяет общий лимит задачи и не исправляет
блокировку CDN. Пример отдельной проверки медленного соединения с 60 секундами:

```text
docker compose run --rm --no-deps -e MEDIA_SOCKET_TIMEOUT_SECONDS=60 worker python -m lovi diagnose "https://www.instagram.com/reel/DctUTDnNSWx/" --cdn
```

Instagram может не возвращать длительность ролика в метаданных. В этом случае
карточка всё равно открывается, а длительность MP4/MP3 проверяется по скачанному
файлу через ffprobe перед отправкой. Лимиты размера, времени выполнения и запрет
прямых эфиров сохраняются. Файл длиннее `MAX_DURATION_SECONDS` не отправляется;
если измерить длительность файла нельзя, возвращается отдельный код
`duration_unknown` с причиной `file_duration_missing`. Превышение известного
лимита имеет причину `duration_limit`. В диагностике есть `duration_known`
и `max_duration_seconds`; нулевая длительность метаданных означает неизвестное
время, а не слишком длинный ролик.

## Эксплуатация и данные

Redis AOF сохраняет очередь и короткоживущие карточки. Там содержатся user/chat IDs,
ссылки и Telegram file IDs; ограничьте доступ и резервные копии. Cookies и токен
не записываются в Redis. Медиа не хранятся на сервере после задачи; Telegram
сохраняет отправленные файлы по своим правилам. Аварийные каталоги старше тройного
таймаута очищаются при старте worker. Удаление данных пользователя из Telegram
не означает удаления копий на инфраструктуре Telegram.

В логах приложения — ID задачи, код результата и время, без содержимого cookies,
токенов и прокси. На уровне платформы ограничьте исходящий доступ приватным сетям,
не используйте недоверенные прокси и не монтируйте Docker socket в приложение.
Для `MAX_UPLOAD_MB` / concurrency установите лимиты диска контейнера на хосте:
проверка свободного места сама по себе не заменяет общую квоту файловой системы.
